# 2. Build the interface and the scene as separate layers

TIMEFOLD is easier to understand when the interface and world have a narrow boundary. The DOM owns readable text/buttons/dialogs. The WebGL renderer owns meshes, camera, and light. The controller translates input and callbacks between them.

## A minimal scene exercise

In a separate Vite study entry, after installing Three.js, this is a complete tiny scene core:

```ts
import * as T from 'three';

const canvas = document.createElement('canvas');
document.body.append(canvas);
const renderer = new T.WebGLRenderer({ canvas, antialias: true });
renderer.setPixelRatio(Math.min(devicePixelRatio, 1.5));
const scene = new T.Scene();
scene.background = new T.Color('#292d34');
const camera = new T.PerspectiveCamera(45, 1, 0.1, 100);
camera.position.set(4, 3, 6);
camera.lookAt(0, 0, 0);
scene.add(new T.HemisphereLight('#f2eee6', '#22242d', 2));
const cube = new T.Mesh(
  new T.BoxGeometry(1, 1, 1),
  new T.MeshStandardMaterial({ color: '#c1947d' }),
);
scene.add(cube);
function resize() {
  renderer.setSize(innerWidth, innerHeight);
  camera.aspect = innerWidth / innerHeight;
  camera.updateProjectionMatrix();
}
resize();
addEventListener('resize', resize);
renderer.setAnimationLoop(() => renderer.render(scene, camera));
```

Every object has a separate job: `renderer` draws, `scene` contains, `camera` projects, `geometry` supplies shape, and `material` supplies a lit surface. A standard material needs light. `updateProjectionMatrix` is required after changing aspect/FOV.

This exercise intentionally omits the production world's shadow management, cleanup, picking, travel, and reduced-motion scheduling. Its continuously running `setAnimationLoop` is a learning shortcut: the actual lifecycle pauses hidden pages and stops scheduling a settled reduced-motion view. Compare the [world facade](../reference/world.md), [scene modules](../reference/scene.md), and [performance notes](../reference/performance.md).

## Add a DOM overlay

Place a heading and button in a positioned container above the canvas. Let a decorative overlay use `pointer-events: none`, while real buttons accept input. If a full-screen transparent element catches pointer events, the canvas underneath cannot receive hover/clicks even when it is visible.

The real application uses a fixed viewport canvas, gradient/grain layers, a header, intro, room marker, timeline, and native dialogs. Its layer order and selector details are in [styles](../reference/styles.md). `ui/shell.ts` returns the initial markup, which `main.ts` inserts once; `ui/dom.ts` caches the typed elements. It is not a React render tree. `ui/timeline-view.ts` updates the changing labels and palette without rebuilding the shell.

## Establish a controller contract

The actual world exposes:

```ts
interface World {
  setTime(value: number): void;
  focus(id: ArchiveId | null): void;
  setMotion(value: boolean): void;
  getDiagnostics(): WorldDiagnostics;
  dispose(): void;
}
```

`ArchiveId` comes from `archive.ts`; the copied counter shape `WorldDiagnostics` comes from `scene/types.ts` and is re-exported by `world.ts`. The controller can change time/focus without depending on mesh internals. The world receives `onSelect` and `onHover` callbacks, so it can report a hit without knowing dialog IDs. That is the key linkage to reproduce.

Do not make every mesh responsible for opening its own HTML. Keep content selection centralized, then use a stable category ID to join the representations.

## Prefer a graceful content path

Initialize the DOM controls before attempting WebGL construction. If renderer creation throws, keep an archive index and useful explanation available. This is what the source does. It is not a no-JavaScript fallback; the DOM itself is generated by JavaScript.
